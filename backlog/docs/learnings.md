# Learnings

- Keep `.vscodeignore` in sync when adding new root-level tooling dirs (e.g. `.claude/`, `backlog/`) — otherwise they get bundled into the packaged `.vsix`. (TASK-1)
- `npm test` downloads a VS Code/Electron test host over the network; it times out in sandboxed/offline environments. Fall back to the build gate (`check-types` + `lint`, both already run by `npm run package`) per the release skill, and note the skip rather than blocking. (TASK-1)
- The hardcoded flags in `claude-usage-reader.ts`'s `COMMAND` string (`--live`, `--no-calibrate`) are another repo's CLI surface, not this one's — Scripts' `llm/claudeUsage` renamed/removed both in a same-day commit (TASK-125) with no cross-repo signal, and this extension silently errored on every poll for a full day before it was noticed. When touching this file, re-derive the current flag set from the source (`grep -n '"--' llm/claudeUsage`) rather than trusting the existing string or its comments; don't assume a passing build means the shelled-out command is still valid. The same stale invocation was also copy-pasted into README.md — a code review caught it after the source fix looked complete, so grep docs for the same string too, not just source. ⬆ general (TASK-4)
- `npm run compile` builds the esbuild `dist/` bundle; the smoke-testable `out/` tree (plain `require()`-able CommonJS) is a separate target, `npm run compile-tests` (`tsc -p . --outDir out`). Editing source and re-running only `compile` leaves `out/` stale — a smoke test against it will silently exercise the old code. Rebuild both when verifying a fix this way. (TASK-4)
- `~/.claude/claudeUsage-live-cache.json` (`readSharedLiveCache`) only ever gets populated by `llm/claudeUsage`'s OAuth-endpoint path — `load_live_cache()`'s own docstring calls it "the last good *endpoint* response," and the `claude -p "/usage"` CLI fallback never calls `save_live_cache()`. A design that reads someone else's cache file for a fast path needs to check every write path that cache has, not just the common one — on a machine where the endpoint's token needs a refresh it can't perform (a documented, expected case, not a rare edge), this fast path silently never engages, degrading correctly to the slow path but without the savings the comment describes. Left as a documented limitation rather than widening `claudeUsage`'s cache scope, since that cache dict also carries `retry_after_until` for 429 backoff — folding another source into it risks clearing a live rate-limit block. (TASK-4)
